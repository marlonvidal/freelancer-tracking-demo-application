## Part 1 — Epic Review

### What Went Well

- **Epic 2 retro action items B1, B2, B3 delivered on time.** Conventions centralized in `project-context.md` (B1), recharts SVG Playwright patterns documented as a spike (B2), tag split display contract in Story 3.3 spec (B3). All three completed before Story 3.1 dev started.

- **Story 3.2 had zero debug issues — first in the project.** Direct consequence of B2 patterns being available. No unexpected friction, no mid-story discoveries. The recharts SVG patterns eliminated re-discovery cost for all subsequent stories in the epic.

- **Convention documentation has compounding returns.** Each story in the epic was faster than the last. By Story 3.4, the component pattern (`colorMap`, `hiddenKeys`, `visibleData`, `handleLegendClick`) was replicated mechanically. Cognitive overhead near zero.

- **Strong test growth.** Vitest: 101 → 153 (+52). Playwright E2E: 69 → 103 (+34). All green. A meaningful safety net entering Epic 4, where all three charts must respond to filter changes simultaneously.

- **`isAnimationActive={false}` was a clean, targeted solution.** Added in Story 3.4 to all three `<Pie>` components. Eliminated 400ms+ animation overhead, satisfying AC2 (< 2s render), AC4 (< 500ms chart switch), and AC3 (non-blocking tooltip) in a single 1-line change per file.

- **Responsive layout at 320px confirmed without code change.** The `p-6` padding audit in Story 3.4 showed 272px available width — no overflow. `EarningsDashboard.tsx` layout did not need modification.

### Challenges and Friction (Systems, Not Individuals)

- **Stale TDD RED PHASE comment in E2E spec headers — every story.** Pre-generated ATDD specs ship with a `🔴 RED — All tests skipped` comment. Developers remove `test.skip()` calls but the comment above persists. Flagged in code review for all four stories (3.1, 3.2, 3.3, 3.4). A process gap in the ATDD spec template, not individual negligence.

- **Deferred debt accumulating in clusters.** Eight items added to `deferred-work.md` this epic. Several are the same issue across components:
  - `hiddenKeys` not reset on data change — Story 3.1 and Story 3.3
  - `visibleData` not memoized — Story 3.1 and Story 3.2
  - All-slices-hidden blank chart — Story 3.1 and Story 3.4
  These warrant one dedicated polish story, not scatter-fixes across future epics.

- **`formatCurrency` duplicated across three components.** Deliberately deferred to Epic 6 per spec instructions. Three divergence points now exist. Risk: a future formatting change applied to one file but not the others produces user-visible inconsistency in currency display.

- **Pre-existing flaky timing tests revealed under high parallelism.** Stories 1.1 and 3.2 each have a `Date.now()`-before-`page.goto()` timing assertion that fails only when 100+ tests run simultaneously (CPU contention). Revealed by Story 3.4's large E2E run. Workaround: `retries: 1` added. Root fix: timer should start after navigation completes.

- **A1 carry-forward (App.tsx import normalization) orphaned across two epics.** Never addressed because `App.tsx` was not in any story's file list. Confirmed: opportunistic action items do not ship without explicit scheduling.

## Key Takeaways

1. **Documentation investment has a measurable payoff.** B1, B2, B3 from Epic 2's retro produced Story 3.2's zero-debug implementation — the first clean story in the project. The compounding effect is real: document patterns once, eliminate re-discovery cost for every subsequent story.

2. **Opportunistic action items don't ship.** A1 crossed two epics because `App.tsx` was never in a story's file list. If it matters, schedule it. Story 4.4 exists specifically because of this lesson.

3. **Debt clusters in related components should be resolved together in one dedicated story.** `hiddenKeys`, `formatCurrency`, all-slices-hidden — same family of fixes, three components. Story 4.4 addresses them holistically rather than leaving them to accumulate through Epic 5 and beyond.
