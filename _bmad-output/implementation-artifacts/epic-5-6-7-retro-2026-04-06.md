### What Went Well

- **Pre-implementation audit pattern compounded across all three epics.** Each story opened with an explicit "What Is ALREADY Complete" section. In Epic 6, FR28/FR29/FR32 were confirmed pre-done. In Epic 7, FR33/FR35/FR38/NFR-A2/NFR-A4/NFR-A6/NFR-A7 were all confirmed pre-done from earlier epics. Zero wasted re-implementation.

- **D1 finally has traction — three consecutive clean ATDD specs.** After failing twice (Stories 4.1 and 4.2) and being auto-patched twice, the ATDD spec template produced zero stale-comment findings across Stories 5.1, 6.1, and 7.1. The enforcement mechanism (hard gate, not calendar commitment) worked.

- **Blocking review findings: 0 across three epics.** All review findings were either auto-patched (Story 5.1: 1 patch) or formally deferred. No story was held for rework.

- **Test baseline growth was disciplined.** Every epic added meaningful coverage with zero regressions: 207 → 249 → 254 → 264 Vitest; 132 → 141 → 147 → 157 Playwright. Each story stood squarely on the last.

- **The deferred-item resolution pattern worked (Globe button → Story 7.1).** Story 6.1 created `aria-label="Globe"` as a documented shortcut for E2E testability, explicitly deferred it to Epic 7, and Story 7.1 resolved it properly with `t.languageToggleLabel`. That's the system working as designed.

- **Backward-compatible API extension is a clean pattern.** `formatCurrency(value, language?)` added an optional parameter without touching any existing call site. All 249 unit tests passing after the change confirmed zero regressions.

### Challenges and Growth Areas

- **D4 and D5 are now 4+ epics old without landing.** D4 (calendar popover auto-close) was targeted at Story 4.4, then "Epic 6 or 7 UX review," then Story 7.1 — and still hasn't shipped. D5 (chart view selector inconsistency) has the same history. Items without a concrete story file and no next-epic escape hatch do not ship.

- **The `[P0]` calculation error E2E test is a zombie — it always passes and proves nothing.** `story-7-1-...-atdd.spec.ts`: `loadState()` catches corrupt JSON and returns `getDefaultState()` (5 sample tasks), so neither the error state nor the empty state renders. Both `if` branches are skipped. The test passes unconditionally. A `[P0]` that cannot fail is worse than no test.

- **The accessibility epic shipped with a WCAG 2.1 violation.** The dark mode toggle button in `Header.tsx` has no `aria-label` — a clear WCAG 2.1 SC 4.1.2 gap. It was identified and deferred in Story 7.1's code review. Story 7.1 was the accessibility story. There is no Story 7.2 in the plan.

- **`deferred-work.md` is write-only.** Story 7.1 added five new items. One was resolved (Globe button — done in Story 7.1). The rest accumulated. The file has no resolution column, no aging mechanism, and no review cadence.

- **`aria-label` without `role="region"` on the metrics div does not create a named landmark.** The spec and implementation both agreed on this pattern — but per ARIA spec, `aria-label` on a generic `<div>` without `role="region"` is silently ignored by most screen readers for landmark navigation. The `aria-live` works; the named landmark does not appear in screen reader region traversal.

## Key Takeaways

1. **Pre-audit + "already done" documentation is the highest-leverage story preparation practice in this codebase.** It prevented wasted work in every single story of Epics 5–7 and should be the mandatory opening section of every future story file.

2. **Deferred items only ship when they have story files.** D4 drifted through five epics with five different target assignments and never landed. Story 7.2 is its first story file. That is the difference.

3. **A `[P0]` that always passes is a category error, not a test.** The zombie calculation error test must be replaced. The principle: every `[P0]` should be written such that removing the feature it tests causes it to fail.

4. **"Accessibility epic complete" is not the same as "WCAG compliant."** The accessibility story identified and deferred a WCAG 2.1 SC 4.1.2 violation. WCAG compliance requires tooling verification (axe-core), not just story completion.

5. **The demo application MVP is complete in scope. Story 7.2 makes it complete in quality.**
