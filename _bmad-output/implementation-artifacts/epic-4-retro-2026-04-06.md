## Part 1 — Epic Review

### What Went Well

- **100% delivery with zero production incidents.** All four stories shipped cleanly. Test baseline grew from 153 Vitest + 103 Playwright (Epic 3 end) to 207 Vitest + 132 Playwright — meaningful quality floor entering Epic 5.

- **Inline spike resolution was the right call.** C2 (shadcn/ui date picker) and C3 (keyboard accessibility E2E) were resolved directly in story dev notes rather than separate spike documents. This kept the dev agent contextually complete without requiring separate artifacts. Story 4.1 had zero component discovery friction; Story 4.3's keyboard tests passed on first run.

- **Pattern reuse compounding across stories.** Story 4.2 was measurably faster than 4.1 — the `data-testid` discipline, `Translations` type export, and persistence test pattern from 4.1 were replicated mechanically in 4.2. Story 4.3 then added ARIA attributes to existing components without touching behavior. Each story stood on the last.

- **Story 4.4 honored a debt commitment.** Five deferred items from Epic 3 — `hiddenKeys` reset, `formatCurrency` extraction, all-slices-hidden empty state, timing test fix, App.tsx import normalization — all closed in one focused polish story. The carry item A1 (App.tsx) finally crossed two epics and landed.

- **Code review auto-fix pattern effective.** Review findings were caught and patched without blocking story completion. 0 `decision-needed` findings across the epic — all patches or defers.

- **`data-testid` strategy eliminates bilingual test fragility.** Targeting test IDs rather than text content means the same E2E test runs correctly in both English and Portuguese. No language-conditional test branching required.

### Challenges and Friction (Systems, Not Individuals)

- **C1 failed again — stale RED PHASE comment persisted into Stories 4.1 and 4.2.** In the Epic 3 retro, Murat committed to fixing the ATDD spec template before Story 4.1. The stale `🔴 RED PHASE` header comment appeared in Story 4.1's ATDD spec and again in Story 4.2's. Both were auto-patched in code review. Root cause: the action item had no story, no file, no hard gate — it was scheduled against a calendar event that had no enforcement mechanism.

- **Double-commit pattern in Stories 4.1 and 4.3.** Each of these stories landed two commits rather than the standard one. Story 4.4's dev notes explicitly flagged Story 4.3's two commits as "unusual." The pattern suggests something required a correction after initial implementation — tests failed on first run, or a review finding needed a re-pass. Not recorded in completion notes.

- **Story 4.2 ATDD seed bug.** The visual distinction test used `page.evaluate()` spreading over an empty `{}` object, which produced an incomplete state rejected by `coercePersisted`. The fix was to provide a complete valid `EarningsDashboardPersistedState`. This is a pattern gap — nowhere in `project-context.md` does it document that `page.evaluate()` state seeds must be complete, not partial.

- **Calendar popover auto-close left unaddressed.** Story 4.1 code review deferred popover auto-close ("can be addressed in Story 4.4 UX polish"). Story 4.4's final ACs didn't include it. The item is now informally open with no owner or target. Users must manually close the calendar popover after selecting both dates.

- **Chart view selector inconsistency.** Date range and billable controls are now button groups; the chart view control remains a `<Select>` dropdown. This visual inconsistency was discussed during Epic 4 planning and intentionally descoped, but it's not formally tracked as deferred debt.

## Key Takeaways

3. **Debt clusters closed together stay closed.** Story 4.4 paid down five related items in one focused story. That cluster is now closed and the codebase is measurably healthier. Contrast with D4 and D5 — items that weren't formally deferred are already drifting.
